# INDETERMINATE -> REAL TRANSITION

## Goal

Describe the minimal transition between the indeterminate state `I` and the real-number set `R` without identifying `I` with a real number and without adding an arbitrary real value.

## 1. State space

```text
State := Indeterminate | Resolved(r),  r ∈ R
```

The two regions are distinct:

```text
I ∉ R
Resolved(r) carries r ∈ R
```

## 2. Resolution relation

The bridge is a relation, not an unconditional function:

```text
Resolve(I, r, e)
```

where:

- `I` is the indeterminate source;
- `r ∈ R` is the real endpoint;
- `e` is evidence that selects/justifies that endpoint.

Without `e`, no real endpoint is produced.

## 3. Transition parameter

Introduce only a path parameter:

```text
τ ∈ [0,1]
```

Interpretation:

```text
τ = 0  : fully indeterminate
0 < τ < 1 : resolving
τ = 1  : resolved real endpoint
```

The parameter is descriptive; it does not by itself choose `r`.

## 4. Transition path

For a fixed justified endpoint `r` and evidence `e`:

```text
γ(r,e,0) = I
γ(r,e,1) = Resolved(r)
```

Intermediate states are tagged transition states:

```text
γ(r,e,τ) = Resolving(r,e,τ),  0 < τ < 1
```

This avoids pretending that an indeterminate object can be numerically interpolated with a real number before a numerical embedding has been defined.

## 5. Triadic payload during resolution

Every transition state carries:

```text
(R_weight, I_weight, U_weight)
```

with the qualitative constraints:

```text
at τ = 0:
  U_weight is dominant

as τ increases:
  U_weight does not increase
  R_weight does not decrease

at τ = 1:
  R_weight is dominant
  U_weight = 0
```

No numerical formula for the weights is assumed yet.

## 6. Minimal monotonicity law

The transition is oriented:

```text
Indeterminate
  -> Resolving
  -> Resolved(r)
```

and never reverses unless a separate reverse rule is explicitly introduced.

## 7. Real endpoint condition

A transition is complete only when all three hold:

```text
EndpointReal:
  r ∈ R

ResolutionEvidence:
  e proves/selects r

IndeterminacyClosed:
  U_weight = 0
```

Then:

```text
Resolve(I,r,e)
----------------
I ->* Resolved(r)
```

## 8. Producer generated by the transition

A real producer must contain at minimum:

```text
RealProducer := {
  endpoint : R
  evidence : ResolutionEvidence(endpoint)
  path     : I ->* Resolved(endpoint)
  closed   : IndeterminacyClosed(endpoint)
}
```

This is the first object that can legitimately replace:

```text
PRODUCERS: <VAZIO>
```

## 9. External-certificate chain

Only after a `RealProducer` exists:

```text
I
-> resolution evidence
-> RealProducer
-> EXTERNAL_GAP
-> EXTERNAL_CERTIFICATE
-> FINAL_ROOT
-> FINAL_PROOF
```

Until then:

```text
PRODUCERS: <VAZIO>
EXTERNAL_GAP: BLOCKED_BY_PRODUCER
EXTERNAL_CERTIFICATE: BLOCKED_BY_EXTERNAL_GAP
FINAL_ROOT: BLOCKED_BY_EXTERNAL_CERTIFICATE
FINAL_PROOF: BLOCKED_BY_FINAL_ROOT
```

## 10. Relation to the primitive law

The original primitive transition remains:

```text
0/1 -> 1/1
```

The indeterminate-to-real bridge is a resolution layer around states; it does not redefine standard arithmetic and does not identify `0/0` with an ordinary real number.

## 11. What is still not assumed

No additional claim is made about:

- which real `r` must be selected;
- uniqueness of the selected real;
- a metric distance from `I` to `R`;
- continuity in the standard real topology;
- standard complex arithmetic;
- field structure on the indeterminate state;
- probability weights;
- a numerical convergence rate.

Those require separate definitions/proofs.
